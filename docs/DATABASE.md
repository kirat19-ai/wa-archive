# Database

SQLite via Drizzle ORM, opened with WAL, `foreign_keys = ON`, and a busy timeout.
Designed for millions of messages.

## Conventions

- **Primary keys** are app-generated UUID strings — immutable local identity
  (spec §7). Never a phone number (can change) or a raw WhatsApp id.
- **Timestamps** are epoch milliseconds (`INTEGER`), matching the normalized
  transport types.
- **Isolation**: every WhatsApp-scoped row carries `account_id`, and
  `(account_id, whatsapp_*_id)` is unique — WhatsApp ids are **not** assumed
  globally unique across accounts (spec §18).

## Tables

`users`, `whatsapp_accounts`, `contacts`, `chats`, `messages`, `media`,
`message_reactions`, `message_edits`, `message_links`, `groups`,
`group_participants`, `sync_jobs`, `media_jobs`, `backup_records`, `devices`,
`sessions`, `audit_logs`, `settings`, plus the `messages_fts` FTS5 virtual table.

## Full-text search

`messages_fts` is an FTS5 external-content table over `messages(text, caption)`,
kept in sync by triggers. Search is scoped per account, or across an explicit set
of authorized accounts, always ordered by rank.

## Migrations

Generated by drizzle-kit from `packages/database/src/schema.ts`:

```bash
npm run db:generate
```

Migrations are applied automatically on `openDatabase()`. The FTS5 virtual table
and triggers are (re)applied idempotently after every migration.

## Repositories

`createRepositories(db)` returns account-isolated repositories
(`accounts`, `chats`, `messages`, `contacts`, `search`). Every WhatsApp-scoped
method takes an `accountId` and filters on it, so a query physically cannot
return another account's rows.
